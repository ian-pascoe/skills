New `validating-ui` skill: validates the UI a change touches. It runs each surface the change touches at the base and the head, has impeccable's `audit` and then its `critique` review the head, each in its own subagent, and fixes what's worth fixing: every problem the change introduced at P0 or P1, every render failure it introduced, every acceptance criterion the UI fails, and the advisory findings it agrees with that stay inside the change's spec. Then it screenshots the base and the fixed head at the sizes they ship at and records a short demo of the change's main flow working. It hands back the findings, the evidence, and a `## UI` report showing each surface's base beside its head, and posts the screenshots and demo to the PR: uploaded where the code host allows, the demo as video where the host plays it and otherwise as a GIF, or committed to the repo's one `ui-evidence` branch and linked. It requires [`impeccable`](https://github.com/pbakaus/impeccable), plus [`agent-browser`](https://github.com/vercel-labs/agent-browser) for web pages and Electron apps or [`agent-desktop`](https://github.com/vercel-labs/agent-desktop) for native desktop apps, and `ffmpeg` for demos; see the README's UI validation section. On GitHub, uploading needs `gh` 2.105.0 or newer for `--attach`.
